# Cross-owner Reconciliation

> **Local Owner First.** 普通问题由最接近的 Specialist 直接处理；只有多个 Authority 或现实在同一 scope 下真正冲突时，才进行跨 Owner 对账。

## Normalize before resolving

先对齐：

```text
subject and claim
scope / market / user / capability
current, accepted target, or future candidate
environment / host / dependency reality
time and effective version
knowledge basis: accepted, source-derived, observed, inferred, assumed, unknown
```

不同 scope、time plane 或环境的陈述不自动构成冲突。

## Three realities

```text
Accepted Meaning  what an accountable authority currently accepts
Source Reality     what the current implementation expresses
Observed Reality   what a bounded execution actually did
```

**Source Is Not Decision.** **Evidence Bounds Claims.** 三者可以互相挑战，但不能互相冒充。

## Smallest material difference

对账只需表达：

```text
what is currently accepted
what source and observed reality show
which difference materially changes the outcome
which Owner has the decision right
which smallest ownership, boundary, behavior, or knowledge change resolves it
which local reversible work can continue while one decision remains open
```

不默认创建 ADIR、Architecture Health、Decision Calculus、评分或中央 Trace。

## Unknown boundary

Unknown 留在它能改变的 Owner 中，只阻塞受影响的承诺。不得把 `unknown`、`not observed`、`contradicted` 和 `failed` 合并，也不得让实施 Agent 替产品、权限、风险或不可逆决定 Authority 接受结果。

## Project surface first

如果争议持续来自找不到正式入口、事实 Writer、Composition Root、运行命令或 First Wrong State，先改善项目工程表面；不要用更厚的 Review Artifact 遮盖不可发现的系统。
