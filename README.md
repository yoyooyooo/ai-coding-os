## Package mirror boundary

Agent Kit is the admission authority for nine outbound Suite mappings under `skills/**`: eight shared core Skills plus the supporting `effect-server-module-design`. Synpraxis and SMIP contribute reviewed deltas to the shared eight-Skill core roster; SMIP separately owns the candidate body for `effect-server-module-design`. The route is `declared project source -> Agent Kit upstream admission -> accepted snapshot -> ai-coding-os outbound projection`. This repository is not a second Skill source: Agent Kit collect skips mapped Suite content, and export writes only to a clean mirror.

Goal Proof is outside those outbound mappings. Its user-invoked Skill under `experiments/goal-proof/skill/**` remains experiment-owned and uses a separate bidirectional Agent Kit edge; it is not part of the eight-Skill semantic core, the supporting Server Module Skill, the core Router, or the Suite ZIP.

This repository owns package-facing surfaces: `README.md`, `README.zh-CN.md`, `skills/README.md`, `CONTRIBUTING.md`, `docs/**`, `VERSION`, `CHANGELOG.md`, and `release/**`. Those package and release metadata remain local and do not become Skill content Authority.

Configuration or a staged export alone does not prove admission or release. Claims about current package content require the accepted Agent Kit commit plus the exact mirror commit; npm publication requires separate release evidence. `release/**` and [`release/README.md`](release/README.md) remain historical pre-import evidence unless explicitly regenerated by the release workflow.

AI Coding OS assumes a capable Agent can plan and implement correctly when the project makes meaning, authority, boundaries, defaults, runtime entry points, and evidence clear. The package therefore provides a self-navigating knowledge network rather than a mandatory workflow.
