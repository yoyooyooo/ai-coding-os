## Package mirror boundary

Mapped content for the eight tracked core Skills under `skills/**` is an outbound package projection of Agent Kit's admitted snapshot. The candidate Skill bodies and attachments are sourced from Synpraxis; the route is `Synpraxis -> Agent Kit upstream admission -> accepted snapshot -> ai-coding-os outbound projection`. This is not a second Skill source: Agent Kit collect does not collect mapped core Skill content from this mirror. Route body, reference, template, and example changes for this roster to Synpraxis; after upstream admission, Agent Kit export updates a clean mirror. Export skips a dirty mirror to protect package work in progress.

Goal Proof is outside that core outbound ownership. Its user-invoked Skill under `experiments/goal-proof/skill/**` remains experiment-owned and is governed by a separate bidirectional Agent Kit mapping; it is not part of the eight-Skill core roster, core Router, or core ZIP.

This repository owns package-facing surfaces: `README.md`, `README.zh-CN.md`, `skills/README.md`, `CONTRIBUTING.md`, `docs/**`, `VERSION`, `CHANGELOG.md`, and `release/**`. Those package and release metadata remain local and do not become Skill content Authority.

This Ticket records a routing/config contract only. Current docs/config do not prove Synpraxis source merge, AK admission, export, package commit/push, or npm release. Ticket 04 supplies live evidence. `release/**` and [`release/README.md`](release/README.md) remain historical pre-import evidence; do not regenerate them as part of this Ticket.

AI Coding OS assumes a capable Agent can plan and implement correctly when the project makes meaning, authority, boundaries, defaults, runtime entry points, and evidence clear. The package therefore provides a self-navigating knowledge network rather than a mandatory workflow.
