# Product Definition Templates

Use these templates selectively. They are destination-neutral and should follow the repository's existing document homes, metadata, status vocabulary, and naming rules.

| Template | Use when |
| --- | --- |
| `product-brief.md` | Framing a product or capability and its outcomes |
| `source-synthesis.md` | Several sources, current behaviors, or claims compete |
| `scope-baseline.md` | A version boundary must be accepted and protected from drift |
| `clarification-register.md` | Conflicts, gaps, assumptions, risks, or questions need owners and decisions |
| `decision-packet.md` | Stakeholders need a recommendation and options before deciding |
| `product-decision-record.md` | A durable product decision has been accepted |
| `product-model.md` | Terms, actors, objects, relationships, lifecycle, and cross-cutting concepts need one model |
| `workflow-specification.md` | A cross-role process needs happy, alternate, exception, and recovery paths |
| `state-machine.md` | One object's lifecycle requires explicit transitions and invalid actions |
| `business-rule-catalog.md` | Rules, enums, calculations, or precedence span several requirements |
| `raci-permission-matrix.md` | Responsibility, authority, assignment, or data visibility is complex |
| `metric-dictionary.md` | Metrics or dashboard figures require stable definitions |
| `quality-attribute-requirements.md` | Cross-cutting measurable product constraints matter |
| `module-prd.md` | A business capability is ready for detailed specification |
| `design-handoff.md` | Design needs complete product states and constraints |
| `acceptance-criteria.md` | Requirements need observable acceptance behavior |
| `uat-scenario.md` | Business users need end-to-end validation scenarios |
| `requirements-traceability-matrix.md` | Risk or coordination justifies durable source-to-acceptance tracing |
| `change-impact-assessment.md` | Accepted behavior, scope, rule, metric, or permission is changing |
| `alignment-meeting-pack.md` | A decision meeting must be focused and close into authoritative artifacts |
