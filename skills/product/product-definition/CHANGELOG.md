# Changelog

## v2.2.2 — Source claim closure

- Added the minimal `implementation` Source Synthesis claim kind for static source, route, schema, migration, and table existence.
- Kept `observed-behavior` reserved for bounded execution or observation rather than source presence.

## v2.2.1 — Implementation / observation terminology closure

- Renamed `current-behavior-derived` to `observed-behavior-derived`; the label now requires bounded execution or observation.
- Classified legacy source and AI-generated code as current-implementation and migration evidence rather than runtime behavior.
- Updated source synthesis terminology without adding a parallel implementation-status taxonomy.

## v2.2.0 — Authority-led default judgment

- Made ordinary reversible details inferable from the current Product Baseline, SSoT, accepted rules, and nearby project patterns.
- Limited Decision Packets to unresolved choices that materially change product scope, shared meaning, workflow/state semantics, permissions, rules, metrics, acceptance, or version promises.
- Clarified that durable issue records require decision, traceability, risk, or cross-owner handoff pressure; local issues remain inline.
- Preserved local blocker isolation, proportional artifacts, and delivery/acceptance claim boundaries without adding templates or schemas.

## v2.1.0 — Suite handoff compatibility

- Made Product Design Handoff explicitly supply accepted Requirement, Rule, and AC IDs without owning IA, layout, frontend state, components, or test lanes.
- Added one-way InterfaceCapability handoff guidance and eval coverage.
- Added safe Product-to-Docs and delivery-evidence reference rules without promoting accepted targets into verified implementation.
- Migrated eval assets to the Suite eval schema and updated the package self-check.

## v2.0.0 — Generic product-definition system

- Expanded the core model from `Baseline / Model / Challenge` to `Baseline / Model / Challenge / Trace`.
- Added explicit source registration, atomic claim synthesis, confidence-versus-authority handling, and current-behavior classification.
- Added version scope baselines with retained, introduced, changed, migrated, retired, excluded, deferred, and blocked treatments.
- Added product-model guidance for actors, objects, relationships, invariants, state dimensions, files, artifacts, and cross-module ownership.
- Added workflow guidance for alternate, exception, recovery, termination, migration, handoff, time, concurrency, retry, and stale-data behavior.
- Added reusable guidance and templates for business rules, enumerations, permissions, RACI, metrics, and measurable product quality attributes.
- Added decision packets before durable Product Decision Records, product impact matrices, recommendation quality checks, and decision closure rules.
- Changed blocking behavior so unresolved decisions isolate only affected scope while unaffected product work continues.
- Added stakeholder alignment and meeting-pack guidance that prevents meeting notes from becoming a shadow product SSoT.
- Expanded module PRDs, acceptance criteria, UAT, design handoff, requirements traceability, and product change-impact assessment.
- Added artifact-selection and readiness guidance to avoid mandatory document trees and over-documentation.
- Added optional stable identifier guidance and a conservative mechanical artifact scanner.
- Added package self-checks, scanner tests, interface metadata, and expanded evaluation cases.
- Kept the Skill domain-neutral and destination-neutral; no industry-specific objects, roles, policies, or workflows were added.
- Kept `SKILL.md` as a branch-aware execution entry: runs enter at the earliest unresolved product step, while artifact selection, readiness, traceability, identifiers, and scanner detail remain in their owner-local references.

## v1.x — Initial product-definition skill

- Established source-versus-decision-versus-specification-versus-delivery boundaries.
- Added product brief, clarification register, PDR, module PRD, state machine, acceptance criteria, and UAT templates.
- Added source synthesis, product modeling, challenge/decision, PRD/acceptance, and product/technical-boundary references.
