# Self-Application and Cargo Cult

> **Do Not Build Coconut Airports.** Visible form without the local mechanism, pressure, and feedback that made it useful is cargo cult, even when the form came from an earlier version of this Suite.

The Suite must obey its own principles. A system that teaches Earned Shape while preserving unused layers, schemas, and workflows is internally inconsistent.

## Self-application questions

```text
does every Skill own an independent semantic problem?
does every reference answer a stable question?
does the main Skill agree with leaf references and templates?
are portable defaults clearly distinct from invariants?
are tools separated from semantic owners?
can an Agent enter from any relevant pressure without a mandatory root path?
does the package improve project legibility or create a private world to learn first?
```

## Cargo cult signals

```text
copying Planner/Coder/Reviewer roles without a measured coordination problem
adding a Port around every library because "clean architecture" uses Ports
creating all docs homes or file suffixes for symmetry
adopting microservices, events, Actors, or Effect as identity rather than mechanism
keeping evaluation/release artifacts because mature projects have them
using a template's completeness as proof of product quality
```

## Mechanism before form

For every convention or pattern, state the pressure it solves. If the pressure is absent, the form should be optional or removed.

## Broken windows

Old contradictory references, duplicate doctrine, and dead templates silently teach Agents the wrong behavior. Repair, lower, or delete them rather than relying on a warning in the main Skill.

## Periodic global view

Local changes can be individually reasonable while the Suite gradually grows a second operating system. Occasionally inspect activation surface, owner overlap, language consistency, hidden templates, and leaf doctrine as a whole.
