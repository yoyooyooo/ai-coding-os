# Knowledge Portfolio

> **Mechanisms Must Earn Their Keep.** Every instruction, reference, template, convention, schema, tool, or Skill should justify its context and maintenance cost through protected meaning or recurring pressure.

Treat the Skill network as a portfolio of meanings, causal models, defaults, examples, templates, and tools with different costs and half-lives.

## Possible homes

### Main `SKILL.md`

Keep distinctions that should shape most uses of the owner and that change material judgment.

### Reference

Keep conditional depth, mechanism-specific knowledge, edge cases, or examples that matter only under identifiable pressure.

### Portable convention

Keep a deterministic default for an underdetermined cross-project choice when it repeatedly lowers search, review, and tooling cost.

### Template or example

Keep only when repeated use saves real reasoning and the artifact does not induce unnecessary structure.

### Project knowledge

Move local authority, adopted conventions, commands, terminology, and architecture facts into the project.

### Type, test, command, or tool

Move preventable execution failure into a more reliable mechanical owner.

### Separate tool or overlay

Use for scanners, generators, machine schemas, regulated artifact suites, or explicit architecture reviews with real consumers.

## Portfolio questions

```text
does the content change an independent decision?
is the failure recurring across fresh projects?
is the knowledge stable enough to remain portable?
does a shorter route or project affordance solve the problem better?
is the content duplicated because ownership is unclear?
what is the maintenance and context cost?
```

## Preserve high-entropy concepts

Keep short concepts that reliably reactivate important judgment, such as:

```text
Project Authority First
Source Is Not Decision
Evidence Bounds Claims
Earned Shape
Feedback Horizon
Fact Authority
Prototype versus Tracer
```

Do not expand each concept into a universal procedure.

## Remove silent bloat

Hidden template families, duplicated READMEs, old doctrine in leaf references, and tools masquerading as Skills can dominate behavior even when the main Skill is concise. Review the whole package, not only `SKILL.md`.
