# Failure Attribution

| Attribution | Typical response |
| --- | --- |
| Skill defect | bounded body edit, deletion, or clearer owner interface |
| Execution lapse | replay, better Harness, compatible reminder, or no canonical edit |
| Routing defect | change description, Router, or Owner Map |
| Retrieval defect | improve progressive disclosure or Reference pointer |
| Tool-interface defect | change Tool/Schema/API instead of adding prose |
| Project knowledge gap | update or route to project Authority |
| Semantic-owner gap | add external/adjacent owner; do not let current Skill absorb it |
| Evaluator defect | repair Oracle or case; never train toward a false score |
| Model capability limit | narrow support claim or add a compatibility overlay |
| Stochastic noise | repeat seeds/runs; do not update from one draw |

Analyze successful trajectories too: a correct result reached through an unsafe,
unrepeatable, over-costly, or authority-violating path can still reveal a defect.
