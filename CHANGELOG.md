# Changelog

## 0.4.2 — Dogfood Contract Closure

- Preserved Preset profile provenance as separate `requested`, `defaults_added`, `dependency_added`, and `resolved` sets; the default `agent-entry` no longer masquerades as user intent.
- Removed TypeScript filename-pattern leakage from `monorepo-core`, made `typescript-node` own TypeScript application patterns, routed React through the TypeScript profile, and kept language-neutral verification profiles free of TypeScript test patterns.
- Bound Effect Kit P3 Descriptors to an existing project Harness entry and project-supplied observables/claim ceiling instead of fabricating recovery coverage.
- Added configurable bounded verification-command timeout, process-tree termination, bounded output, structured filesystem/rollback errors, and lock-release assertions to the Effect Kit.
- Made the canonical audit a real release sidecar, normalized machine-local path/compiler diagnostics, and added byte-for-byte cross-path determinism checks for ZIP, audit, manifest, change report, and composition review.
- Rejected known Harness v2 camelCase/legacy aliases without closing all extension fields, and added the minimal Product Source Synthesis `implementation` claim kind.
- Kept doctrine, Router, Core Skill roster, Proof axes, Evidence Envelope, and external execution-method boundaries frozen.

## 0.4.1 — Machine Contract And Candidate Truth Closure

- Made the Core ZIP self-contained: `skills/README.md` uses bundle-local links, `skills/VERSION` supplies the Core version, and the bundle-local audit/builder run without repository-root files.
- Bound release provenance to a canonical `source_tree_sha256`; the builder rejects stale or unrelated audit reports and the manifest records the same source identity.
- Localized Docs Governance and Architecture blockers so undecidable slices stop only affected mutations while unrelated classification, topology, migration, and proof work continues.
- Separated current implementation from observed behavior in Product and Docs terminology; source-only evidence no longer receives a behavior-derived label.
- Separated InterfaceCapability definition lifecycle from Harness/delivery evidence by removing automatic proof promotion and the `regression` definition status.
- Made Preset render output an honest `candidate-snapshot`: generated AGENTS/Standards/ADRs no longer self-assert adoption, and technical fact-writer maps moved from SSoT to `docs/architecture/fact-authority-map.md`.
- Simplified Evidence Envelope v2 to an optional direction-neutral claim-boundary shape while retaining constrained version-1 reader compatibility and rejecting mismatched legacy direction/source-kind pairs.
- Added static Proof Surface support through `dependency_reality: [none]`, rejected v2 legacy/canonical field double-writing, and updated Effect API App Kit P3 to emit a schema-validated Harness Descriptor v2.
- Added bounded Suite-audit subprocess timeouts and targeted negative tests for schema mismatches, static proof, legacy field mixing, P3 command requirements, and stale release provenance.

## 0.4.0 — Minimal Knowledge Kernel Convergence

- Compressed cross-Skill doctrine into six non-procedural principles: Project Authority First, Question-scoped Ownership, One Scoped Meaning/One Current Home, Binding Constraint Is Not Semantic Ownership, Evidence Bounds Claims, and Route/Impact Obligation.
- Replaced the remaining numbered Authority precedence with question-scoped semantic owners, binding constraints, implementation evidence, and observed evidence.
- Corrected source claims: source establishes implementation structure and static properties; runtime, reachability, deployment, and environment behavior require executed or observed Evidence.
- Made Router output natural language by default and downgraded structured Handoff, Decision Queue, and YAML routing shapes to optional consumer-earned forms.
- Removed the redundant Human-Agent Documentation SOP and kept Artifact Graph as an opt-in navigation inventory.
- Tightened Product Definition's default judgment so reversible local detail is inferred while authority-changing uncertainty is isolated without blocking unrelated work.
- Made Preset incremental adoption the explicit existing-repository default, stopped generating empty Product/SSoT/Architecture/Harness layers, validated declared managed surfaces instead of a complete tree, and removed duplicated product meanings from source-naming output.
- Narrowed Adjacent Owner lists, clarified owner-declared source vocabulary scope, and added guarded cross-domain terms without introducing a global ontology or new Core schema.
- Pruned overlapping Docs/Product static eval scenarios while adding ten composition cases for scoped coexistence, impact obligations, local continuation, owner selection, and claim boundaries; independent model-run quality remains unclaimed.

## 0.3.0 — Core Knowledge Network Boundary

- Reframed the core AI Coding OS as a 14-Skill, multi-entry project knowledge/standards/Authority network: Routes are edges, owner-local Passes are coverage, and execution strategy remains external.
- Moved Goal Proof out of the core Router, roster, audit, schemas, bundle, and docs layer into `experiments/goal-proof/**`; collapsed four public phase Skills into one user-invoked experimental Skill with conditional references.
- Split repository validation into `check:core`, `check:goal-proof-experiment`, and aggregate `check`; the core Suite ZIP now excludes experiments, CLI packages, project docs, and release scripts.
- Generalized Evidence Translation from Goal-specific adapters to selected-execution-method handoffs while preserving claim ceilings and owner-local lifecycle.
- Replaced Preset/AGENTS/docs `Read First` sequences with unordered Knowledge Surfaces, Discovery Surfaces, and Routes; retained marker-bounded merge and staged upgrade safety.
- Rewrote Docs Governance around Authority, Routes, Earned Shape, and Evidence; scanners now validate declared discovery edges without enforcing a reading workflow.
- Recalibrated all core Skill Pass sections as coverage, added the missing Product Harness output contract, strengthened boundary evals, and kept real state-machine/transaction sequences owner-local.
- Added a superseding ADR for the Core/Experiment boundary and preserved historical Goal evidence without rewriting old paths.
